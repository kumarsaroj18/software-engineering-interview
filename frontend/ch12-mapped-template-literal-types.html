Chapter 12: Mapped & Template Literal Types

“What are mapped types and template literal types? How would you use them to type a REST API client?”

Key Takeaway: Mapped types iterate over keys to transform one type into another ({[K in keyof T]: ...}). Template literal types enable string manipulation at the type level. Combined, they can generate typed API clients from route definitions, transform event handler types from event names, and create CSS-in-JS type safety — all at compile time with zero runtime cost.

Interviewer's Intent

What the interviewer is really asking

The interviewer wants to verify you can:

  • Understand type-level computation — Can you think of types as programs that run at compile time?
  • Transform types systematically — Can you derive one type from another without manual duplication?
  • Apply template literals beyond simple strings — Can you parse, validate, and transform string patterns at the type level?
  • Build real abstractions — Can you type complex patterns like REST clients, event systems, or CSS-in-JS?
  • Know the limits — Do you understand when type-level complexity hurts more than it helps?

60-Second Answer

Quick answer for time-pressured interviews

Mapped types iterate over a set of keys to produce a new type. The syntax is {[K in Keys]: ValueType}. They power built-in utilities like Partial, Required, Pick, and Record.

Template literal types use backtick syntax at the type level to create string patterns: `on${Capitalize<Event>}`. They distribute over unions and support infer for extraction.

Combined, they enable typing a REST client from route definitions:

// Define routes as a type
type Routes = {
  '/users': { GET: User[]; POST: User };
  '/users/:id': { GET: User; PUT: User; DELETE: void };
};

// Extract path params from string pattern
type ExtractParams<T extends string> =
  T extends `${string}:${infer Param}/${infer Rest}`
    ? { [K in Param | keyof ExtractParams<Rest>]: string }
    : T extends `${string}:${infer Param}`
      ? { [K in Param]: string }
      : {};

// Generate typed client using mapped + template literal types
type ApiClient = {
  [Path in keyof Routes]: {
    [Method in keyof Routes[Path]]:
      ExtractParams<Path & string> extends infer P
        ? keyof P extends never
          ? () => Promise<Routes[Path][Method]>
          : (params: P) => Promise<Routes[Path][Method]>
        : never;
  };
};

Interview tip: Lead with the mental model (iteration + string manipulation), give one concrete use case (API client or event handlers), then mention performance awareness.

Mapped Types Internals

How mapped types work under the hood

Basic Syntax

// The fundamental mapped type pattern
type MappedType = {
  [K in Keys]: ValueType;
};

// Concrete example: make all properties optional
type MyPartial<T> = {
  [K in keyof T]?: T[K];
};

// Make all properties readonly
type MyReadonly<T> = {
  readonly [K in keyof T]: T[K];
};

How Iteration Works

Given: type User = { name: string; age: number; email: string }

MyPartial<User> iterates:
  Step 1: K = "name"  → name?: string
  Step 2: K = "age"   → age?: number
  Step 3: K = "email" → email?: string

Result: { name?: string; age?: number; email?: string }

Modifiers: + and -

// Adding modifiers (+ is implicit)
type ReadonlyOptional<T> = {
  +readonly [K in keyof T]+?: T[K];
};

// Removing modifiers
type Mutable<T> = {
  -readonly [K in keyof T]: T[K];
};

type Required<T> = {
  [K in keyof T]-?: T[K];
};

// Remove both readonly AND optional
type Concrete<T> = {
  -readonly [K in keyof T]-?: T[K];
};

Homomorphic vs Non-Homomorphic

// Homomorphic: preserves modifiers from the original type
// (iterates over keyof T — preserves structure)
type HomomorphicExample<T> = {
  [K in keyof T]: T[K] | null;
};

// Non-homomorphic: creates new structure
// (iterates over arbitrary keys — no modifier preservation)
type NonHomomorphic = {
  [K in 'a' | 'b' | 'c']: boolean;
};

// Why it matters:
interface Original {
  readonly name: string;
  age?: number;
}

// Homomorphic preserves readonly and optional
type Wrapped = HomomorphicExample<Original>;
// { readonly name: string | null; age?: number | null }

// Record is non-homomorphic — no modifier preservation
type Fresh = Record<keyof Original, boolean>;
// { name: boolean; age: boolean } — no readonly, no optional

Key insight: Homomorphic mapped types (those iterating over keyof T where T is a type parameter) distribute over union types. This is why Partial<T> works correctly with unions — each union member is mapped independently, preserving the discriminated union structure.

// Homomorphic distribution example:
type Circle = { kind: 'circle'; radius: number };
type Square = { kind: 'square'; side: number };
type Shape = Circle | Square;

// Partial is homomorphic (iterates keyof T where T is a param):
type PartialShape = Partial<Shape>;
// = Partial<Circle> | Partial<Square>
// = { kind?: 'circle'; radius?: number } | { kind?: 'square'; side?: number }
// Discriminated union preserved!

// Non-homomorphic (iterating over a concrete key set):
type NonHomomorphic = { [K in keyof Shape]?: Shape[K] };
// = { kind?: 'circle' | 'square' }  — only common keys, union structure lost!

Key Remapping (as clause)

TS 4.1+ as clause for renaming and filtering keys

Basic Key Remapping

// Syntax: [K in Keys as NewKey]: ValueType
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

interface Person {
  name: string;
  age: number;
}

type PersonGetters = Getters<Person>;
// { getName: () => string; getAge: () => number }

Filtering Keys with never

// Return never from as clause to filter out keys
type FilterByType<T, U> = {
  [K in keyof T as T[K] extends U ? K : never]: T[K];
};

interface Mixed {
  name: string;
  age: number;
  active: boolean;
  email: string;
}

type StringProps = FilterByType<Mixed, string>;
// { name: string; email: string }

type NumericProps = FilterByType<Mixed, number>;
// { age: number }

// Remove specific keys
type RemovePrefix<T, Prefix extends string> = {
  [K in keyof T as K extends `${Prefix}${string}` ? never : K]: T[K];
};

interface Config {
  _internal: boolean;
  _debug: boolean;
  apiUrl: string;
  timeout: number;
}

type PublicConfig = RemovePrefix<Config, '_'>;
// { apiUrl: string; timeout: number }

Transforming Key Names

// camelCase to snake_case
type CamelToSnake<S extends string> =
  S extends `${infer Head}${infer Tail}`
    ? Tail extends Uncapitalize<Tail>
      ? `${Lowercase<Head>}${CamelToSnake<Tail>}`
      : `${Lowercase<Head>}_${CamelToSnake<Tail>}`
    : S;

type SnakeCaseKeys<T> = {
  [K in keyof T as CamelToSnake<string & K>]: T[K];
};

interface ApiResponse {
  userName: string;
  createdAt: Date;
  isActive: boolean;
}

type SnakeResponse = SnakeCaseKeys<ApiResponse>;
// { user_name: string; created_at: Date; is_active: boolean }

Practical: Event Map Generation

type EventMap<T> = {
  [K in keyof T as `on${Capitalize<string & K>}`]:
    (event: T[K]) => void;
};

interface Events {
  click: MouseEvent;
  keydown: KeyboardEvent;
  scroll: Event;
}

type EventHandlers = EventMap<Events>;
// {
//   onClick: (event: MouseEvent) => void;
//   onKeydown: (event: KeyboardEvent) => void;
//   onScroll: (event: Event) => void;
// }

Remember: The as clause was introduced in TypeScript 4.1. Before that, key transformation required intermediate types and Pick/Omit combinations.

Template Literal Types

String manipulation at the type level

Basic Syntax

// Template literal types use backtick syntax
type Greeting = `Hello, ${string}`;

const valid: Greeting = "Hello, world";  // ✓
const invalid: Greeting = "Hi, world";   // ✗ Error

// With specific unions
type Color = 'red' | 'blue' | 'green';
type Size = 'sm' | 'md' | 'lg';

type ClassName = `${Size}-${Color}`;
// "sm-red" | "sm-blue" | "sm-green" |
// "md-red" | "md-blue" | "md-green" |
// "lg-red" | "lg-blue" | "lg-green"

Distributive Behavior with Unions

// Template literals distribute over unions (cross product)
type Vertical = 'top' | 'bottom';
type Horizontal = 'left' | 'right';

type Position = `${Vertical}-${Horizontal}`;
// "top-left" | "top-right" | "bottom-left" | "bottom-right"

// Multiple unions multiply
type A = 'a' | 'b';     // 2 members
type B = '1' | '2';     // 2 members
type C = 'x' | 'y' | 'z'; // 3 members

type Combined = `${A}-${B}-${C}`;
// 2 × 2 × 3 = 12 members

Extracting Parts with infer

// Parse route parameters
type ExtractParam<T extends string> =
  T extends `${string}:${infer Param}/${infer Rest}`
    ? Param | ExtractParam<Rest>
    : T extends `${string}:${infer Param}`
      ? Param
      : never;

type Params = ExtractParam<'/users/:userId/posts/:postId'>;
// "userId" | "postId"

// Split string into tuple
type Split<S extends string, D extends string> =
  S extends `${infer Head}${D}${infer Tail}`
    ? [Head, ...Split<Tail, D>]
    : [S];

type Parts = Split<'a.b.c.d', '.'>;
// ["a", "b", "c", "d"]

// Extract domain from email
type ExtractDomain<T extends string> =
  T extends `${string}@${infer Domain}`
    ? Domain
    : never;

type Domain = ExtractDomain<'user@example.com'>;
// "example.com"

Recursive Template Literals

// Replace all occurrences of a substring
type ReplaceAll<
  S extends string,
  From extends string,
  To extends string
> = From extends ''
  ? S
  : S extends `${infer Before}${From}${infer After}`
    ? `${Before}${To}${ReplaceAll<After, From, To>}`
    : S;

type Result = ReplaceAll<'foo-bar-baz', '-', '_'>;
// "foo_bar_baz"

// Trim whitespace
type TrimLeft<S extends string> =
  S extends ` ${infer Rest}` ? TrimLeft<Rest> : S;

type TrimRight<S extends string> =
  S extends `${infer Rest} ` ? TrimRight<Rest> : S;

type Trim<S extends string> = TrimLeft<TrimRight<S>>;

type Trimmed = Trim<'  hello  '>;
// "hello"

Recursion depth: TypeScript limits type recursion depth to ~50 levels by default. With tail-call optimization (tail-recursive conditional types, TS 4.5+), the limit increases to ~1000. Keep non-tail-recursive template types shallow; restructure deep recursion to be tail-recursive.

String Manipulation Types

Built-in and custom string type utilities

Built-in Intrinsic Types

// These are compiler intrinsics — not implementable in userland
type Upper = Uppercase<'hello'>;       // "HELLO"
type Lower = Lowercase<'HELLO'>;       // "hello"
type Cap = Capitalize<'hello'>;        // "Hello"
type Uncap = Uncapitalize<'Hello'>;    // "hello"

// They distribute over unions
type Events = 'click' | 'focus' | 'blur';
type PrefixedEvents = `on${Capitalize<Events>}`;
// "onClick" | "onFocus" | "onBlur"

Custom String Manipulation

// kebab-case to camelCase
type KebabToCamel<S extends string> =
  S extends `${infer Head}-${infer Tail}`
    ? `${Head}${KebabToCamel<Capitalize<Tail>>}`
    : S;

type Camel = KebabToCamel<'background-color'>;
// "backgroundColor"

// camelCase to kebab-case
type CamelToKebab<S extends string> =
  S extends `${infer Head}${infer Tail}`
    ? Tail extends Uncapitalize<Tail>
      ? `${Lowercase<Head>}${CamelToKebab<Tail>}`
      : `${Lowercase<Head>}-${CamelToKebab<Tail>}`
    : S;

type Kebab = CamelToKebab<'backgroundColor'>;
// "background-color"

// PascalCase to words
type PascalToWords<S extends string> =
  S extends `${infer Head}${infer Tail}`
    ? Tail extends Uncapitalize<Tail>
      ? `${Head}${PascalToWords<Tail>}`
      : `${Head} ${PascalToWords<Tail>}`
    : S;

type Words = PascalToWords<'MyComponentName'>;
// "My Component Name"

Parsing Patterns

// Parse a semver string
type ParseSemver<T extends string> =
  T extends `${infer Major}.${infer Minor}.${infer Patch}`
    ? { major: Major; minor: Minor; patch: Patch }
    : never;

type Version = ParseSemver<'1.2.3'>;
// { major: "1"; minor: "2"; patch: "3" }

// Parse URL pattern
type ParseURL<T extends string> =
  T extends `${infer Protocol}://${infer Host}/${infer Path}`
    ? { protocol: Protocol; host: Host; path: Path }
    : T extends `${infer Protocol}://${infer Host}`
      ? { protocol: Protocol; host: Host; path: '' }
      : never;

type URL = ParseURL<'https://api.example.com/v1/users'>;
// { protocol: "https"; host: "api.example.com"; path: "v1/users" }

Pro tip: String manipulation types shine for validating string formats at compile time — API routes, CSS class names, environment variable names, and configuration keys.

Combining Mapped + Template Literal Types

The power combo: iteration meets string manipulation

Generating Event Handler Types

type EventConfig = {
  click: { x: number; y: number };
  focus: { target: HTMLElement };
  change: { value: string; previousValue: string };
};

// Generate on + Capitalize handlers
type EventHandlers<T> = {
  [K in keyof T as `on${Capitalize<string & K>}`]:
    (payload: T[K]) => void;
};

type Handlers = EventHandlers<EventConfig>;
// {
//   onClick: (payload: { x: number; y: number }) => void;
//   onFocus: (payload: { target: HTMLElement }) => void;
//   onChange: (payload: { value: string; previousValue: string }) => void;
// }

// Also generate has + Capitalize checkers
type EventCheckers<T> = {
  [K in keyof T as `has${Capitalize<string & K>}Listener`]: boolean;
};

type Checkers = EventCheckers<EventConfig>;
// { hasClickListener: boolean; hasFocusListener: boolean; hasChangeListener: boolean }

Transforming API Routes to Methods

type HttpMethod = 'GET' | 'POST' | 'PUT' | 'DELETE';

type ApiRoutes = {
  'GET /users': { response: User[] };
  'POST /users': { body: CreateUserDto; response: User };
  'GET /users/:id': { response: User };
  'PUT /users/:id': { body: UpdateUserDto; response: User };
  'DELETE /users/:id': { response: void };
};

// Parse "METHOD /path" into structured type
type ParseRoute<T extends string> =
  T extends `${infer Method} ${infer Path}`
    ? { method: Method; path: Path }
    : never;

// Generate method names from routes
type RouteToMethodName<T extends string> =
  T extends `${infer Method} /${infer Path}`
    ? `${Lowercase<Method>}${Capitalize<PathToName<Path>>}`
    : never;

type PathToName<T extends string> =
  T extends `${infer Segment}/${infer Rest}`
    ? `${Segment}${Capitalize<PathToName<Rest>>}`
    : T extends `:${infer Param}`
      ? `By${Capitalize<Param>}`
      : T;

CSS Property Typing

type CSSProperty = 'margin' | 'padding' | 'border';
type Direction = 'top' | 'right' | 'bottom' | 'left';

// Generate directional CSS properties
type DirectionalCSS = {
  [P in CSSProperty as `${P}-${Direction}`]: string;
};
// { "margin-top": string; "margin-right": string; ... }

// Responsive breakpoint variants
type Breakpoint = 'sm' | 'md' | 'lg' | 'xl';
type SpacingProp = 'p' | 'px' | 'py' | 'm' | 'mx' | 'my';

type ResponsiveProps = {
  [K in SpacingProp | `${Breakpoint}:${SpacingProp}`]?: number;
};
// { p?: number; px?: number; "sm:p"?: number; "sm:px"?: number; ... }

Mental model: Think of mapped types as Array.map() for type properties, and template literals as string interpolation for type-level strings. Combined, they're like Object.entries().map(([key, value]) => [transform(key), transform(value)]).

Typing REST API Routes

Full implementation: route string → typed params → typed client

Step 1: Extract Path Parameters

// Parse :param segments from a route string
type ExtractPathParams<T extends string> =
  T extends `${string}:${infer Param}/${infer Rest}`
    ? { [K in Param | keyof ExtractPathParams<`/${Rest}`>]: string }
    : T extends `${string}:${infer Param}`
      ? { [K in Param]: string }
      : {};

// Test it
type UserParams = ExtractPathParams<'/users/:userId'>;
// { userId: string }

type PostParams = ExtractPathParams<'/users/:userId/posts/:postId'>;
// { userId: string; postId: string }

type NoParams = ExtractPathParams<'/users'>;
// {}

Step 2: Define Route Configuration

interface RouteConfig {
  response: unknown;
  body?: unknown;
  query?: Record<string, string>;
}

// Define your API routes
interface ApiRouteMap {
  'GET /users': {
    response: User[];
    query: { page?: string; limit?: string };
  };
  'POST /users': {
    response: User;
    body: { name: string; email: string };
  };
  'GET /users/:id': {
    response: User;
  };
  'PUT /users/:id': {
    response: User;
    body: Partial<User>;
  };
  'DELETE /users/:id': {
    response: void;
  };
  'GET /users/:userId/posts/:postId': {
    response: Post;
  };
}

Step 3: Build the Typed Client

// Parse route key into method + path
type ParseRouteKey<T extends string> =
  T extends `${infer Method extends string} ${infer Path}`
    ? { method: Method; path: Path }
    : never;

// Build request options based on route config
type RequestOptions<
  Path extends string,
  Config extends RouteConfig
> = (ExtractPathParams<Path> extends infer P
  ? keyof P extends never ? {} : { params: P }
  : {}) &
  (Config extends { body: infer B } ? { body: B } : {}) &
  (Config extends { query: infer Q } ? { query: Q } : {});

// The typed API client
type TypedApiClient<Routes extends Record<string, RouteConfig>> = {
  request<K extends keyof Routes & string>(
    route: K,
    ...args: keyof RequestOptions<
      ParseRouteKey<K>['path'],
      Routes[K]
    > extends never
      ? []
      : [options: RequestOptions<ParseRouteKey<K>['path'], Routes[K]>]
  ): Promise<Routes[K]['response']>;
};

// Usage
declare const api: TypedApiClient<ApiRouteMap>;

// ✓ No params needed
await api.request('GET /users');

// ✓ Params required
await api.request('GET /users/:id', { params: { id: '123' } });

// ✓ Body required
await api.request('POST /users', {
  body: { name: 'John', email: 'john@example.com' }
});

// ✗ Error: missing params
await api.request('GET /users/:id');  // Error!

Step 4: Method-Based Client (Alternative)

// Group by HTTP method for a more ergonomic API
type MethodClient<Routes extends Record<string, RouteConfig>> = {
  get<P extends ExtractByMethod<Routes, 'GET'>>(
    path: P,
    ...args: BuildArgs<P, Routes[`GET ${P}`]>
  ): Promise<Routes[`GET ${P}`]['response']>;

  post<P extends ExtractByMethod<Routes, 'POST'>>(
    path: P,
    ...args: BuildArgs<P, Routes[`POST ${P}`]>
  ): Promise<Routes[`POST ${P}`]['response']>;

  put<P extends ExtractByMethod<Routes, 'PUT'>>(
    path: P,
    ...args: BuildArgs<P, Routes[`PUT ${P}`]>
  ): Promise<Routes[`PUT ${P}`]['response']>;

  delete<P extends ExtractByMethod<Routes, 'DELETE'>>(
    path: P,
    ...args: BuildArgs<P, Routes[`DELETE ${P}`]>
  ): Promise<Routes[`DELETE ${P}`]['response']>;
};

type ExtractByMethod<
  Routes extends Record<string, RouteConfig>,
  Method extends string
> = {
  [K in keyof Routes]: K extends `${Method} ${infer Path}` ? Path : never;
}[keyof Routes];

type BuildArgs<Path extends string, Config> =
  Config extends RouteConfig
    ? keyof RequestOptions<Path, Config> extends never
      ? []
      : [options: RequestOptions<Path, Config>]
    : never;

Real-world usage: Libraries like ts-rest and zodios use this pattern to generate fully typed API clients from contract definitions. The pattern scales well up to ~100 routes before hitting performance limits.

Typing Event Handlers from String Patterns

on('click', handler) with full type safety

Basic Typed Event Emitter

interface EventMap {
  click: { x: number; y: number; button: number };
  keydown: { key: string; code: string; ctrlKey: boolean };
  resize: { width: number; height: number };
  'custom:update': { data: unknown; timestamp: number };
}

// Typed EventEmitter
class TypedEmitter<Events extends Record<string, unknown>> {
  private listeners = new Map<string, Set<Function>>();

  on<K extends keyof Events & string>(
    event: K,
    handler: (payload: Events[K]) => void
  ): this {
    if (!this.listeners.has(event)) {
      this.listeners.set(event, new Set());
    }
    this.listeners.get(event)!.add(handler);
    return this;
  }

  off<K extends keyof Events & string>(
    event: K,
    handler: (payload: Events[K]) => void
  ): this {
    this.listeners.get(event)?.delete(handler);
    return this;
  }

  emit<K extends keyof Events & string>(
    event: K,
    payload: Events[K]
  ): this {
    this.listeners.get(event)?.forEach(fn => fn(payload));
    return this;
  }
}

// Usage — fully typed
const emitter = new TypedEmitter<EventMap>();

emitter.on('click', ({ x, y }) => {});       // ✓ x, y inferred
emitter.on('keydown', ({ key }) => {});       // ✓ key inferred
emitter.emit('resize', { width: 100, height: 50 }); // ✓

Wildcard and Namespaced Events

// Support namespaced events: "module:event"
type NamespacedEvents = {
  'auth:login': { userId: string };
  'auth:logout': { reason: string };
  'data:update': { entity: string; id: string };
  'data:delete': { entity: string; id: string };
};

// Extract events by namespace
type EventsByNamespace<
  Events extends Record<string, unknown>,
  NS extends string
> = {
  [K in keyof Events as K extends `${NS}:${infer Name}`
    ? Name
    : never
  ]: Events[K];
};

type AuthEvents = EventsByNamespace<NamespacedEvents, 'auth'>;
// { login: { userId: string }; logout: { reason: string } }

type DataEvents = EventsByNamespace<NamespacedEvents, 'data'>;
// { update: { entity: string; id: string }; delete: { ... } }

DOM Event Map Typing

// Type-safe DOM event delegation
type DOMEventHandler<
  E extends keyof HTMLElementEventMap
> = (event: HTMLElementEventMap[E]) => void;

// Generate prop types for React-like components
type DOMEventProps = {
  [K in keyof HTMLElementEventMap as `on${Capitalize<K>}`]?:
    DOMEventHandler<K>;
};

// Usage in component props
interface ButtonProps extends DOMEventProps {
  label: string;
  variant: 'primary' | 'secondary';
}

// Now ButtonProps has onClick, onKeydown, onFocus, etc.
// all properly typed with correct event types

Pattern recognition: The on${Capitalize<K>} pattern appears in React, Vue, Svelte, and many UI libraries. Understanding how it works at the type level helps you extend it for custom event systems.

Typing CSS-in-JS

CSS property names as template literals, responsive variants, theme tokens

CSS Property Names

// Map camelCase JS properties to kebab-case CSS
type CSSProperties = {
  backgroundColor: string;
  fontSize: string;
  borderRadius: string;
  marginTop: string;
};

type KebabCase<S extends string> =
  S extends `${infer Head}${infer Tail}`
    ? Tail extends Uncapitalize<Tail>
      ? `${Lowercase<Head>}${KebabCase<Tail>}`
      : `${Lowercase<Head>}-${KebabCase<Tail>}`
    : S;

};
// { "background-color": string; "font-size": string; ... }

Record, Pick, Omit — Internals

How standard utility types are implemented as mapped types

Record Implementation

// Record creates a non-homomorphic mapped type
type Record<K extends keyof any, T> = {
  [P in K]: T;
};

// It does NOT preserve modifiers because it's non-homomorphic
type Example = Record<'a' | 'b', number>;
// { a: number; b: number } — no readonly, no optional

// Common use cases
type StatusMap = Record<'loading' | 'success' | 'error', boolean>;
type EntityStore<T> = Record<string, T>;

Pick Implementation

// Pick is homomorphic — preserves modifiers
type Pick<T, K extends keyof T> = {
  [P in K]: T[P];
};

interface User {
  readonly id: string;
  name: string;
  email?: string;
}

type Picked = Pick<User, 'id' | 'email'>;
// { readonly id: string; email?: string }
// ↑ readonly preserved   ↑ optional preserved

Omit Implementation

// Omit uses Exclude + Pick (or direct mapped type)
type Omit<T, K extends keyof any> = Pick<T, Exclude<keyof T, K>>;

// Alternative direct implementation
type OmitDirect<T, K extends keyof any> = {
  [P in keyof T as P extends K ? never : P]: T[P];
};

// Important: Omit does NOT constrain K to keyof T
type Test = Omit<User, 'nonexistent'>; // No error! Returns User

// Strict version that catches typos
type StrictOmit<T, K extends keyof T> = {
  [P in keyof T as P extends K ? never : P]: T[P];
};

type Bad = StrictOmit<User, 'nonexistent'>; // ✗ Error!

Limitations and Strict Alternatives

// Problem: Omit loses index signature information
interface Indexed {
  [key: string]: unknown;
  name: string;
  age: number;
}

type Omitted = Omit<Indexed, 'name'>;
// { [key: string]: unknown; age: number } — index preserved

// Problem: Pick/Omit with discriminated unions
type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'square'; side: number };

type Broken = Omit<Shape, 'kind'>;
// { radius: number } | { side: number }? NO!
// Actually: {} — keyof Shape is only 'kind' (common keys),
// so Exclude<'kind', 'kind'> = never, giving Pick<Shape, never> = {}

// Solution: distributive Omit
type DistributiveOmit<T, K extends keyof any> =
  T extends any ? Omit<T, K> : never;

type Fixed = DistributiveOmit<Shape, 'kind'>;
// { radius: number } | { side: number } — correct!

Common pitfall: Omit and Pick flatten discriminated unions. Always use distributive versions (T extends any ? ... : never) when working with unions.

Performance Considerations

When mapped/template types slow the compiler

Complexity Explosion

// ⚠️ Template literal unions multiply combinatorially

type B = '1' | '2' | '3' | '4' | '5'; // 5

// === Complete Type-Safe REST Client ===

// Path parameter extraction
type ExtractParams<T extends string> =
  T extends `${string}:${infer Param}/${infer Rest}`
    ? { [K in Param | keyof ExtractParams<`/${Rest}`>]: string }
    : T extends `${string}:${infer Param}`
      ? { [K in Param]: string }
      : {};

// Route definition
interface RouteDefinition {
  response: unknown;
  body?: unknown;
  query?: Record<string, string | number | boolean>;
  headers?: Record<string, string>;
}

// API specification
interface ApiSpec {
  'GET /users': {
    response: { id: string; name: string; email: string }[];
    query: { page?: number; limit?: number; search?: string };
  };
  'POST /users': {
    response: { id: string; name: string; email: string };
    body: { name: string; email: string };
  };
  'GET /users/:id': {
    response: { id: string; name: string; email: string };
  };
  'PUT /users/:id': {
    response: { id: string; name: string; email: string };
    body: { name?: string; email?: string };
  };
  'DELETE /users/:id': {
    response: void;
  };
  'GET /users/:userId/posts/:postId/comments': {
    response: { id: string; text: string }[];
    query: { sort?: 'asc' | 'desc' };
  };
}

// Build request configuration
type RequestConfig<
  Path extends string,
  Def extends RouteDefinition
> = (keyof ExtractParams<Path> extends never
  ? {}
  : { params: ExtractParams<Path> }) &
  (Def extends { body: infer B } ? { body: B } : {}) &
  (Def extends { query: infer Q } ? { query?: Q } : {}) &
  (Def extends { headers: infer H } ? { headers?: H } : {});

// Parse "METHOD /path" string
type ParseMethod<T extends string> =
  T extends `${infer M} ${string}` ? M : never;
type ParsePath<T extends string> =
  T extends `${string} ${infer P}` ? P : never;

// The client type
type RestClient<Spec extends Record<string, RouteDefinition>> = {
  request<Route extends keyof Spec & string>(
    route: Route,
    ...config: keyof RequestConfig<ParsePath<Route>, Spec[Route]> extends never
      ? [config?: {}]
      : [config: RequestConfig<ParsePath<Route>, Spec[Route]>]
  ): Promise<Spec[Route]['response']>;
};

// Implementation
function createClient<Spec extends Record<string, RouteDefinition>>(
  baseUrl: string
): RestClient<Spec> {
  return {
    async request(route: string, config: any = {}) {
      const [method, pathTemplate] = route.split(' ');
      let path = pathTemplate;

      // Replace path params
      if (config.params) {
        for (const [key, value] of Object.entries(config.params)) {
          path = path.replace(`:${key}`, value as string);
        }
      }

      // Build URL with query params
      const url = new URL(path, baseUrl);
      if (config.query) {
        for (const [key, value] of Object.entries(config.query)) {
          if (value !== undefined) url.searchParams.set(key, String(value));
        }
      }

      const response = await fetch(url.toString(), {
        method,
        headers: { 'Content-Type': 'application/json', ...config.headers },
        body: config.body ? JSON.stringify(config.body) : undefined,
      });

      if (!response.ok) throw new Error(`HTTP ${response.status}`);
      return method === 'DELETE' ? undefined : response.json();
    },
  } as RestClient<Spec>;
}

// Usage
const api = createClient<ApiSpec>('https://api.example.com');

// Fully typed — IDE autocomplete works!

  query: { page: 1, limit: 10 },
});
// users: { id: string; name: string; email: string }[]

const user = await api.request('GET /users/:id', {

Event Emitter with Mapped Types

// === Type-Safe Event Emitter ===

type EventHandler<T> = (payload: T) => void;
type WildcardHandler = (event: string, payload: unknown) => void;

class StrictEmitter<Events extends Record<string, unknown>> {
  private handlers = new Map<string, Set<Function>>();
  private wildcardHandlers = new Set<WildcardHandler>();

  on<K extends keyof Events & string>(
    event: K,
    handler: EventHandler<Events[K]>
  ): () => void {
    if (!this.handlers.has(event)) {
      this.handlers.set(event, new Set());
    }
    this.handlers.get(event)!.add(handler);

    // Return unsubscribe function
    return () => {
      this.handlers.get(event)?.delete(handler);
    };
  }

  once<K extends keyof Events & string>(
    event: K,
    handler: EventHandler<Events[K]>
  ): () => void {
    const wrapper: EventHandler<Events[K]> = (payload) => {
      this.handlers.get(event)?.delete(wrapper);
      handler(payload);
    };
    return this.on(event, wrapper);
  }

  onAny(handler: WildcardHandler): () => void {
    this.wildcardHandlers.add(handler);
    return () => { this.wildcardHandlers.delete(handler); };
  }

  emit<K extends keyof Events & string>(
    event: K,
    payload: Events[K]
  ): void {
    this.handlers.get(event)?.forEach(fn => fn(payload));
    this.wildcardHandlers.forEach(fn => fn(event, payload));
  }

  listenerCount<K extends keyof Events & string>(event: K): number {
    return this.handlers.get(event)?.size ?? 0;
  }
}

// Usage
interface AppEvents {
  'user:login': { userId: string; timestamp: number };
  'user:logout': { userId: string; reason: string };
  'data:sync': { entities: string[]; duration: number };
  'error': { code: string; message: string; stack?: string };
}

const bus = new StrictEmitter<AppEvents>();

const unsub = bus.on('user:login', ({ userId, timestamp }) => {
  console.log(`User ${userId} logged in at ${timestamp}`);
});

bus.emit('user:login', { userId: '123', timestamp: Date.now() });
unsub(); // Clean up

Common Mistakes

5 mistakes to avoid with mapped and template literal types

Mistake 1: Infinite Recursion in Template Types

// ❌ Bad: Unbounded recursion
type InfiniteReplace<S extends string, From extends string, To extends string> =
  S extends `${infer Before}${From}${infer After}`
    ? InfiniteReplace<`${Before}${To}${After}`, From, To>  // ⚠️ infinite!
    : S;

// If To contains From, this recurses forever:
// InfiniteReplace<"a", "a", "aa"> → never terminates

// ✓ Good: Only recurse on the remaining portion
type SafeReplace<S extends string, From extends string, To extends string> =
  From extends ''
    ? S
    : S extends `${infer Before}${From}${infer After}`
      ? `${Before}${To}${SafeReplace<After, From, To>}`  // Only recurse on After
      : S;

Mistake 2: Forgetting Distributive Behavior

// ❌ Unexpected: template literals distribute over unions
type Status = 'loading' | 'success' | 'error';
type Prefix = 'is' | 'was';

type Combined = `${Prefix}${Capitalize<Status>}`;
// "isLoading" | "isSuccess" | "isError" |
// "wasLoading" | "wasSuccess" | "wasError"
// → 6 members, not 2!

// ❌ Unexpected with Omit on unions
type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'square'; side: number };

type Bad = Omit<Shape, 'kind'>;
// {} — keyof of a union gives only common keys ('kind'),
// Exclude<'kind','kind'> = never, so Pick<Shape, never> = {}
// NOT what you expected!

// ✓ Good: Use distributive version
type DistributiveOmit<T, K extends keyof any> =
  T extends any ? Omit<T, K> : never;

type Good = DistributiveOmit<Shape, 'kind'>;
// { radius: number } | { side: number }

Mistake 3: Over-Complex Mapped Types

// ❌ Bad: Trying to do too much in one mapped type
type OverEngineered<T> = {
  [K in keyof T as T[K] extends Function
    ? K extends `_${string}` ? never : `public${Capitalize<string & K>}`
    : T[K] extends string
      ? `str${Capitalize<string & K>}`
      : K
  ]: T[K] extends Function
    ? (...args: Parameters<T[K]>) => ReturnType<T[K]>
    : T[K] extends string ? T[K] | null : T[K];
};

// ✓ Good: Break into composable pieces
type PublicMethods<T> = {
  [K in keyof T as K extends `_${string}`
    ? never
    : T[K] extends Function ? K : never
  ]: T[K];
};

type DataFields<T> = {
  [K in keyof T as T[K] extends Function ? never : K]: T[K];
};

// Compose them
type CleanInterface<T> = PublicMethods<T> & DataFields<T>;

Mistake 4: Not Using Key Remapping for Filtering

// ❌ Bad: Using Pick + Extract (verbose, pre-4.1 pattern)
type OnlyStrings<T> = Pick<T, {
  [K in keyof T]: T[K] extends string ? K : never;
}[keyof T]>;

// ✓ Good: Direct filtering with as + never (TS 4.1+)
type OnlyStrings<T> = {
  [K in keyof T as T[K] extends string ? K : never]: T[K];
};

Mistake 5: Confusing Homomorphic Behavior

// ❌ Confusion: Why does my type lose readonly/optional?
interface Source {
  readonly id: string;
  name?: string;
}

// Non-homomorphic: loses modifiers
type Lost = { [K in 'id' | 'name']: Source[K] };
// { id: string; name: string | undefined } — no readonly, not optional!

// ✓ Homomorphic: preserves modifiers
type Preserved = { [K in keyof Source]: Source[K] };
// { readonly id: string; name?: string } — modifiers preserved!

// Rule: Use "K in keyof T" to preserve modifiers.
// Using "K in SomeUnion" creates a fresh type without modifiers.

Debugging tip: When a mapped type behaves unexpectedly, hover over it in your IDE to see the expanded type. Use type Debug = MyType and inspect the tooltip.

When to use mapped/template types vs alternatives
Approach Pros Cons Best For
Mapped Types Zero runtime cost, stays in sync, composable Complex error messages, IDE performance Transforming existing types, utility types
Manual Declarations Clear, readable, good errors Duplication, drift, maintenance burden Small, stable APIs with few variants
Code Generation No compiler overhead, full control Build step needed, generated code in repo Large schemas (OpenAPI, GraphQL, Prisma)

Template Literal Types Compile-time string validation, no runtime Union explosion, recursion limits Route typing, event names, CSS props

──────────────────────────────────────────────
Need to transform an existing type?
  ├── Yes → Mapped type

Pragmatic rule: Use mapped types for DRY type transformations. Use template literals for string-pattern validation. Use code generation when you hit performance walls or need runtime artifacts.

Follow-up Questions

6 follow-up questions with concise answers

Q1: How do you handle optional path parameters like /users/:id?

// Use conditional types to detect optional markers
type ExtractOptionalParams<T extends string> =
  T extends `${string}:${infer Param}?/${infer Rest}`
    ? { [K in Param]?: string } & ExtractOptionalParams<`/${Rest}`>
    : T extends `${string}:${infer Param}?`
      ? { [K in Param]?: string }
      : {};

// Combine required + optional
type AllParams<T extends string> =
  ExtractParams<T> & ExtractOptionalParams<T>;

Q2: What's the difference between mapped types and conditional types?

Mapped types iterate over keys to build object types — they're like map() over properties. Conditional types branch based on type relationships — they're like if/else. They're complementary: mapped types often use conditional types in their value position to compute per-key types.

Q3: How do you test complex mapped types?

// Use type-level assertions
type Expect<T extends true> = T;
type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;

// Write type tests
type Cases = [
  Expect<Equal<ExtractParams<'/users/:id'>, { id: string }>>,
  Expect<Equal<ExtractParams<'/static'>, {}>>,
  Expect<Equal<
    ExtractParams<'/a/:x/b/:y'>,
    { x: string; y: string }
  >>,
];

// Tools: vitest's expectTypeOf, tsd, @type-challenges/utils

Q4: Can mapped types create methods, not just properties?

// Yes — the value type can be a function signature
type Methods<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
  [K in keyof T as `set${Capitalize<string & K>}`]: (v: T[K]) => void;
};

// Note: You can't have multiple mapped types in one type literal.
// Split them and intersect:
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};
type Setters<T> = {
  [K in keyof T as `set${Capitalize<string & K>}`]: (v: T[K]) => void;
};
type Accessors<T> = Getters<T> & Setters<T>;

Q5: How do template literal types interact with generics?

// Template literals are evaluated eagerly with concrete types,
// deferred with generic types

function makeHandler<E extends string>(
  event: E
): `on${Capitalize<E>}` {
  return `on${event.charAt(0).toUpperCase() + event.slice(1)}` as any;
}

const handler = makeHandler('click');
// type: "onClick" — resolved at call site!

// Constraint narrowing works:
function prefixed<T extends 'get' | 'set'>(
  action: T
): `${T}User` {
  return `${action}User` as `${T}User`;
}

Q6: When should you prefer code generation over mapped types?

Prefer code generation when:

  • The source is an external schema (OpenAPI, GraphQL, Protobuf)
  • You need runtime artifacts (validators, serializers) alongside types
  • The type computation exceeds 5M instantiations
  • Error messages become unreadable due to deep type nesting
  • Your IDE becomes unresponsive on the affected files

Tools: openapi-typescript, graphql-codegen, prisma generate, ts-json-schema-generator.

Q7: How do const type parameters (TS 5.0) help with mapped types?

const type parameters force literal type inference without requiring as const at call sites — particularly useful with mapped types and template literals:

// Without const: routes inferred as string[] — loses literal types
function defineRoutes<T extends readonly string[]>(routes: T) { return routes; }
const r = defineRoutes(["/home", "/about"]); // string[]

// With const: preserves literals — enables template literal derivation
function defineRoutes<const T extends readonly string[]>(routes: T) { return routes; }
const r = defineRoutes(["/home", "/about"]); // readonly ["/home", "/about"]

// Now you can use mapped + template types on the inferred literals
type RouteParams<T extends string> = T extends `/${infer Name}` ? Name : never;
type Routes = RouteParams<(typeof r)[number]>; // "home" | "about"

Summary

Mental models and what NOT to say

Mental Models

  • Mapped types = Array.map() for type properties. Iterate over keys, transform each one.
  • Template literal types = string interpolation at compile time. Combine, split, and validate string patterns.
  • as clause = Array.filter() + Array.map() for keys. Rename or remove keys during iteration.
  • Combined = type-level code generator. From a single source of truth, derive all related types.

│                  Mental Model Summary                  │
├──────────────────────────────────────────────────────┤
│                                                      │
│  Source Type ──────────────────────► Derived Types    │
│       │                                    │         │
│       │  Mapped Type                       ├─ API    │
│       │  {[K in keyof T]: ...}             ├─ Events │
│       │                                    ├─ Forms  │
│       │  + Template Literal                ├─ CSS    │
│       │  `on${Capitalize<K>}`             └─ i18n   │
│       │                                              │
│       │  + Key Remapping                             │
│       │  as `new${Name}`                             │
│       │                                              │
│  = Zero-runtime type generation                      │
└──────────────────────────────────────────────────────┘

Key Points to Hit

  • Mapped types use {[K in Keys]: Type} syntax to iterate over keys
  • Modifiers (readonly, ?) can be added (+) or removed (-)
  • Homomorphic mapped types preserve the original type's modifiers
  • Template literal types use backtick syntax and distribute over unions
  • as clause enables key renaming and filtering (TS 4.1+)
  • Combined, they enable typed REST clients, event systems, CSS-in-JS
  • Performance degrades with large unions (>500) and deep recursion (>50 without tail-call optimization, >1000 with)

What NOT to Say

  • ❌ "Mapped types are just like generics" — They're a specific construct for iterating over keys, not a synonym for generics.
  • ❌ "Template literal types are just template strings" — They're compile-time type constructs, not runtime values.
  • ❌ "You should always use mapped types instead of manual types" — Over-engineering types hurts readability and IDE performance.
  • ❌ "Record is the same as a mapped type over keyof T" — Record is non-homomorphic and doesn't preserve modifiers.
  • ❌ "There's no limit to recursion in template types" — TypeScript enforces depth limits (~45-50 levels).
